WorkspaceShell Platform-Admin Handoff Fix — Changed/Added File Hashes
======================================================================

SCOPE: Server-authoritative platform-admin handoff fix for
core/shell/cozy-workspace.js's #resolveCurrentUserRole(userId).

ROOT CAUSE: admin-workspace.html -> /webauthn/session ->
AdminGateCore.decideGateAction() -> correctly recognizes
isPlatformAdmin:true -> Session.establishFromExternalAuth() preserves
roles:["platform-admin"] -> WorkspaceShell.mount() ->
#resolveCurrentUserRole(userId) unconditionally asked the local
window.CozyOS.IdentityEngine.getDashboardConfig(userId), which honestly
returns { available: false } for a server-provisioned administrator
(e.g. "Chalzcozy") with no local IdentityEngine user record -> role
became null -> Administration nav filtered out -> shell fell back to
"applications" -> #hasPermission("applications:view") -> false -> Access
Denied.

FIX: #resolveCurrentUserRole(userId) now reads
window.CozyOS.Session.current() first. For a session established via
establishFromExternalAuth() (snapshot.source === "external"), the
already-verified `roles` array on that snapshot is the sole authority
for admin/developer status -- local IdentityEngine is never consulted
for that branch. Native ("identity"-source) sessions are unaffected --
still resolved via the exact same, unmodified
IdentityEngine.getDashboardConfig() path as before. Mirrors the existing
source-based pattern already established in
core/security/cozy-auth.js's #handleSessionStarted(). Not a second
authorization engine. AdminGateCore, IdentityEngine, and every other
file are unmodified.
