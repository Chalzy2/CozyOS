## 1. Dead/orphaned files inspected

A file is classified dead only after confirming **zero** `<script src="...">` (module or classic) reference to it across every `.html` file in the tree, and zero real `require`/dynamic-load path from a file that is itself loaded.

They were evidently written together, before the real, currently-live `core/modules/*` engines (IdentityEngine, OrganizationRegistry, OrganizationRole, EntitlementEngine, `cozy-storage.js`, `cozy-sync.js`) were built to replace them — and were never deleted.

## 3. Ideas that should NOT be recovered, and why
- **`core/permissions.js`'s hardcoded role dictionary** — directly contradicts the live system's own "zero hardcoding" design principle (verified in `organization-role.js`'s own header comments). Reviving it would reintroduce a second, competing, hardcoded permission authority.
- **`core/tenant.js` as a standalone file** — its one real idea (tenant boundary enforcement) is genuine and missing, but reviving the file itself would create a fourth organization-registration authority alongside `OrganizationRegistry`, `CompanyEngine`, and IdentityEngine's own deprecated fallback. The idea should be re-homed into the Membership milestone's `checkPermission` extension, never the dead file resurrected.
- **`mpesaAgent.js`'s UI/rendering code and hardcoded starting balances** (`floatBalance: 150000.00`, the inline `<div>` HTML strings) — purely MPesaOS-specific presentation, not a reusable concept, and the numbers were placeholder demo data, not real defaults worth preserving.
- **`core/audit.js`/`core/storage.js`/`core/sync.js` as files** — each has a real, already-built, already-loaded successor (`IdentityEngine`/`OrganizationRegistry` audit logs, `cozy-storage.js`, `cozy-sync.js`). Reviving the originals would only reintroduce the exact duplicate-authority risk this audit's own instructions warn against.

## 4. Genuinely uncatered capabilities identified
1. **Business Activity Intelligence / Sales Monitoring** (dormant-product alerts, threshold-based low-balance/low-stock alerts) — no owner anywhere in the live tree.
2. **A live BillingEngine** — the concept exists in detail in the dead file and is actively expected (optional-chained) by two live files, but nothing populates `window.CozyOS.Billing` today.
3. **Receipt/transaction-specific parsing on top of OCR** — plausible partial coverage, not confirmed; flagged for a follow-up, narrower audit rather than assumed missing.
4. **Inventory/stock ledger** — same status as #3: referenced defensively by dead code, not confirmed present or absent in this pass.

## 5. Recommended new Core services (candidates only — not authorized for build)
- `BillingEngine` (real, loaded) — highest priority; closes an already-anticipated dependency of live code.
- `Business Activity Intelligence` service — consumes transaction/order events from any OS, evaluates configurable threshold rules (dormant SKU, low float, low stock), emits events for a Cognitive/Reasoning layer to narrate. Deliberately kept separate from any single application.

## 6. Duplicate/obsolete concepts identified
- Three independent organization-registration authorities (`OrganizationRegistry`, `CompanyEngine`, dead `core/tenant.js`) — flagged here and in the companion Membership audit; not to be extended further without first resolving which is canonical.
- Three "role dictionary" concepts referenced in `entitlement-engine.js`'s own ownership audit (`core/permissions.js`, `core/business/permissions.js`, IdentityEngine's role model) — only the last is live; the other two are dead and obsolete.
